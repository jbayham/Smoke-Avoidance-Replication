# Smoke Avoidance: reproducibility package

This standalone code package reproduces the county-day and county-week analysis, figures, tables and appendix robustness checks for the Smoke Avoidance manuscript. It freezes the accepted analysis following the November 2026 reconciliation, including the corrected spending-date alignment. All inputs, processing stages, and outputs are documented in this repository.

**Start with the [input guide](data/README.md), [manuscript exhibit map](docs/exhibits.md), and [validation status](docs/validation.md).** The exhibit map covers all 30 manuscript exhibits and identifies the code and output files for each. Figure 2 is the author's supplied explanatory schematic; all empirical exhibits are generated by the pipeline.

The standalone package's full rebuild from raw inputs is **not yet verified**: its initial verification run was interrupted before recording a completed stage. Earlier analysis runs and the package's synthetic checks passed; see the validation record for the distinction. For preserving a manuscript version with a DOI, see [archiving a release](docs/archiving.md).

No input datasets are included in the code repository. Non-vendor inputs are available in the separate download below. Several inputs are licensed; some are upstream author-constructed snapshots. The package starts from these explicitly documented inputs and generates the county aggregates, analysis panels, fitted models and exhibits. It does not claim to reconstruct the proprietary place dimension, atmospheric model, or other upstream products from their original observations.

## Download and place the data

**[Download the non-vendor raw-data ZIP (14.50 GB)](https://colostate-my.sharepoint.com/:u:/g/personal/jbayham_colostate_edu/IQCvEzSeT5cuR53Nxt1lPGnfAS_V60LOfJZ_5K5b0L6gwb0?e=8cHSKw).** The archive contains 132 input files, totaling 22.54 GB uncompressed, including smoke, weather, geography, county characteristics and archived routing inputs. Allow space for both the ZIP and its extracted contents.

1. Extract `smoke-avoidance-data-no-vendor-20261121.zip` into a temporary folder with a ZIP64-capable extractor. Python can do this on any supported platform:

   ```text
   python -m zipfile -e smoke-avoidance-data-no-vendor-20261121.zip extracted-inputs
   ```

2. Copy the **contents of `extracted-inputs/smoke-avoidance-data-no-vendor/data/raw/`** into this repository's **`data/raw/`**, preserving all subdirectories. The repository root is the directory containing `run.py`. Keep the code package's existing `data/README.md`; do not copy the archive's outer folder into `data/raw/`.
3. Obtain the licensed vendor inputs separately and place them in `data/raw/vendor/places/`, `data/raw/vendor/spend/`, and `data/raw/vendor/monthly_patterns/`, following the [input guide](data/README.md). The ZIP excludes all vendor inputs, generated panels and fitted models; it alone is insufficient for a full reproduction.
4. After setting up the environment below, run `python run.py check-inputs` from the repository root.

For example, an extracted AQI file must be at `data/raw/aqi/daily_aqi_by_county_2006.csv`, alongside the other input subdirectories under `data/raw/`. The archive also contains a file inventory and `SHA256SUMS` for checking its extracted contents.

## Reproduce the results

1. Install **R 4.5.0** and **Python 3.10 or later**. Add `Rscript` and Python to PATH. See [platform setup](docs/platforms.md) before installing compiled R dependencies.
2. Extract this entire folder to a writable local directory. Run commands from that directory. On Linux/macOS use `python3` if `python` is unavailable; on Windows use `py -3` if needed.
3. Restore the pinned R environment (internet access is needed for installation):

   ```text
   Rscript --vanilla scripts/setup.R
   python run.py doctor
   python run.py test
   ```

4. Follow [Download and place the data](#download-and-place-the-data) for the non-vendor ZIP, then obtain the licensed inputs listed in [data/README.md](data/README.md) and the complete [input manifest](docs/input_manifest.csv). Place all inputs in `data/raw/`. Retain every commercial delivery shard and all shapefile companions.
5. Check the inputs, inspect the execution plan, and run:

   ```text
   python run.py check-inputs
   python run.py plan
   python run.py all --resume
   ```

`all` builds intermediate and final data, estimates the models, generates the main and appendix outputs, and checks the numerical benchmarks. Input checking and SHA-256 fingerprinting can take time for large remote files before estimation starts. No network data downloads or routing API calls occur during the analysis.

For separate phases:

```text
python run.py build --resume
python run.py analysis --resume
python run.py validate
```

`analysis` requires the build outputs already present. To rerun one stage and its prerequisites, use, for example, `python run.py all --stage baseline --resume`. A targeted run does not claim that the entire manuscript has been validated.

## Configuration and progress

Copy `config/local.example.json` to `config/local.json` only if you need different storage locations, an explicit Rscript path, or a different thread count. Relative paths resolve against this package root; absolute paths are permitted in this **untracked local file**. Windows JSON paths can use forward slashes, such as `D:/Smoke Avoidance/data`. Data and output directories must be separate and cannot contain one another. The default is four threads. Python has no third-party package dependencies.

`output/run_status.json` records the requested stages, completion status, input/output hashes and elapsed time. Stage logs are in `output/logs/`; coefficient exports and session information are in `output/checks/`. Successful `--resume` stages are reused only when their code, inputs and declared outputs still match their fingerprints. Without `--resume`, selected generated outputs are rebuilt. Raw files are never deleted by the runner.

One writer is permitted per output directory. If the process is forcibly terminated, inspect `output/.run-lock/owner.json`; remove that lock directory only after confirming that the recorded process has stopped. Then repeat the command with `--resume`. A stage interrupted before completion is rerun. LP-DID also has versioned per-horizon checkpoints. Keep the terminal/session alive or use your operating system's job manager for unattended runs.

The full pipeline is compute- and storage-intensive: the commercial source delivery and gridded inputs are large, and several models use millions of county-days. Use a machine with substantial RAM and scratch storage; the final measured runtime and resource evidence are recorded in [validation status](docs/validation.md). A small laptop may need to run from previously generated **private** intermediate data, or use a compute server. The package does not ship those datasets.

To reduce temporary memory during commercial daily-array expansion, set the environment variable `SMOKE_ARRAY_CHUNK_ROWS=25000` before running the pipeline (default: 500000). This controls computation batch size, not the sample or model. Stages run sequentially; the configured thread count defaults to four. OS CPU affinity and memory limits can additionally constrain the complete process tree on a shared server.

## Accepted conventions and checks

The package retains the accepted analysis: Tuesday–Monday spending weeks and aligned date controls; the `<60` clean-history condition for treated and controls; the strict `<30` robustness restriction on both; the documented November 30 removal; and omission of the redundant weekday/weekend panel from the appendix specification with group-by-date shocks. Routing uses the archived input only. Statistical definitions are not silently updated to new external data vintages or revised AQI conventions.

`validate` requires every mapped exhibit and compares 260 coefficient/standard-error values with the accepted code results at absolute tolerance 0.001, 21 exact sample sizes, spending coefficients and sample sizes, the regional spending aggregation, 42 industry classifications and 42 neighbor shares. The preferred spending elasticity is approximately **0.90449**. Reference values are checks, never inputs to fitting the regressions. PDF bytes may differ across operating systems because of fonts and rendering; numerical comparisons are the reproducibility criterion. See [validation status](docs/validation.md) for what has actually been tested on each platform.

The `.gitignore` excludes data, generated output, local configuration and installed libraries. Confirm the intended code license and any illustration permissions before public release; no new license grant is inferred here.

The exhibit map preserves the last audited figure filenames. For LP-DID, Figure D.1's historical files compare treated-only `<=30` with controls `<60`. The additional approved strict-both-groups `<30` results are also generated as `output/figures/appendix/lpdid_threshold_robustness_{over_60,smoke_as_dv}.pdf`; their three curves explicitly distinguish the main, historical, and strict-both-groups definitions. Candidate counts, used sample sizes and percentage reductions are in `output/models/lpdid_threshold_robustness/`. These are separate, labeled outputs.
